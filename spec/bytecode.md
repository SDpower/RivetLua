# Bytecode 邊界

RivetLua 的 canonical 執行格式是自有 RVLU_V2 bytecode。module 自帶 `format_version`，RVLU encoder 僅輸出 v2，RVLU decode/verify 明確拒絕 v1 與未知版；外部資料必須在載入前通過驗證。V2 位元組格式維持相容，含 20 個 typed opcode、prototype signature/vararg metadata、ClosePath、numeric-for 專用 instruction 與每條 instruction 的 canonical static effect flags；effect 不是 GC heap-edge graph，也不代表可執行 runtime。

第 12 步前置 producer 不改 RVLU_V2 wire/opcode：兩版 native source main prototype 固定參數為 0 且可變參數，入口 `...` 使用 VM 既有 frame／vararg 路徑；舊有合法 raw RVLU 的非 variadic root 仍可解碼。Core `classify_input` 只依固定簽章區分 Source、RawRvlu、Official、UnsupportedBinary；裸 RVLU 的准入重用私藏 RVAS kind 0 None header 與 transport scanner，後續只做普通 RVLU decode/verify，絕不從 pattern 重建 kind 3 helper、NativeDebug 或官方 artifact。官方輸入重用官方 preflight/decode/translate，驗證後保存原有官方 metadata。兩路皆先預付 scanner 工作，再預付後續工作及 temporary／retained；decode 使用借用原 bytes 的 preflight，並核對實際保留容量。外層 RVCT 仍由 SDK 管理，不屬於此語言分類器。

2026-10-03 使用者授權新增純 Rust 的 Lua 5.5.1／5.4.9 官方 binary chunk 輸入／輸出相容層。兩版的 header、prototype、常數、upvalue、debug、strip 與 opcode 各自解碼／編碼；先檢查長度、深度、索引、溢位與配置限額，官方指令先經結構及控制流驗證，才轉成 RVLU_V2 並再次通過既有 verifier。VM 只執行 `VerifiedModule`，不直接執行官方 opcode；官方 chunk 格式相容、Lua 語意相容與 C API／ABI 相容分別驗收。官方 dump 須相容格式、語意及適用的 debug 行為，不要求逐位元組等同官方編譯器。

P05 唯一負責官方 chunk codec／轉譯及不可變 artifact metadata 的驗證與建立；P14 container 保存並傳輸已驗證 artifact，不自行建立可信 metadata 或改寫 RVLU_V2。`VerifiedModule` 區分 `OfficialImport` 與 `NativeRvlu`：前者在同一條可信轉譯路徑保留原始官方 prototype／constant／upvalue／debug 位元組及官方 PC↔RVLU PC 對應；後者即使有經驗證的私有執行計畫，也不因此取得原始官方 IR 身分。RVLU_V2 解碼不推測官方來源，公開的執行計畫候選不能自行附上 artifact。artifact 不含 source AST、closure capture、open upvalue 狀態、執行堆疊、coroutine、root 或宿主資源，也不是執行快照。官方轉譯所需固定 VM 內建函式只經既有一般 `Call` 使用，綁定由 P05 驗證且 guest 無法取得或覆寫；數值迴圈採獨立內部 control tuple，close path 由 CFG 推導。P05 離線轉譯使用 checked 工作額度；轉譯 code／constant 與不可變 artifact 各有獨立 bytes 限額。VM debug 查詢使用既有 capability、fuel 與配置帳本，維持一般 RVLU 的受限除錯政策。P13 load/dump capability 接合及純 Rust 的一般 RVLU→官方 chunk 輸出已有局部驗收；P14 第 9～12 步與本輪總驗收尚待執行。

P05 的 artifact transport 將原封不動的 RVLU_V2 bytes 與獨立 sidecar bytes 交給 P14 容器。Sidecar v1 的 16-byte header 依序是 ASCII `RVAS`（4）、little-endian `u16` version=1（2）、`u8` kind（0=None、1=OfficialImport、2=NativeDebug、3=NativeBuiltinDeclarations）、`u8` reserved=0、little-endian `u64` 總長（含 header）；未宣告尾端、截斷、未知版本／kind、非零 reserved 均拒絕。None 不含 body；OfficialImport body 是 P05 `encode_official_chunk` 等價的來源 chunk bytes（保留現有 debug 或 strip），不直接持久化執行計畫或 PC map。重新載入時 P05 解碼官方來源、再次轉譯／驗證並逐位元組比較**完整 canonical RVLU**；只有一致才建立新的私有 plan、artifact 與 PC map。NaN payload 與負零依位元組身份比較，不能用浮點語意相等代替。NativeDebug body 只保存候選欄位，重載時重新執行 P05 native debug verifier，重算 storage／close groups。

Kind 3 僅供 native 編譯器 table constructor 末位開放欄位的 `RawListWrite`。body 依序為完整 RVLU bytes 的 SHA-256（32 bytes）、little-endian `u32` call count、逐筆固定 24-byte call 宣告、`u8` debug tag（0=無；1=有）及 tag=1 時的 `u32` debug body 長度與既有 kind 2 NativeDebug body。每筆 call 依序為 `u32` prototype、`u32` Call PC、`u16` function base、`u16` source upvalue、`u16` input count（固定 3）、連續三個 `u16` input registers、`u8` open-tail tag（固定 1）、`u16` open-tail register、`u8` builtin tag（固定 0=RawListWrite）；整數皆 little-endian。宣告依 prototype／PC 嚴格遞增，重複、未知 helper、截斷與多餘 bytes 均拒絕。這些 bytes 是不可信候選，不含 execution plan、heap 值或官方 artifact。decode 在預付後續工作額度後才核對 SHA-256，正常解碼並驗證 RVLU，再由實際 prototype／capture 重建 hidden upvalue mappings 與 root binding，逐項驗證 Call／open producer／CFG／私有暫存與 guest 隔離；optional NativeDebug 亦重新驗證與派生 storage／close groups。kind 3 保持 `NativeRvlu` origin，不能與官方來源混合；裸 RVLU bytes 不會自行取得此私有 binding。native→官方輸出只對已驗證的 private plan 轉成兩版 `SETLIST`，不輸出 synthetic binding 或其值。

NativeDebug body 的固定排列是 `source_name` blob、`u32` prototype count，接著逐 prototype：`u32` id、`u32` line_defined、`u32` last_line_defined、`u8` max_active_locals、`u32` line count 與每個 `u32` line、`u32` local count 與逐筆 local、`u32` upvalue-name count 與逐筆名稱。每筆 local 依序是 binding 的 `u32 function`／`u32 ordinal`、`u16 register`、`u8 slot`、`u32 initialized_pc`／`start_pc`／`end_pc`、name blob；每個 upvalue-name 先有 `u8` tag（0=None；1=Some 並隨一個 blob）。Blob 是 little-endian `u32` byte 長度及原始 bytes；所有 count、長度與整體容量均以 checked 算術驗證。沒有第二份 RVLU opcode、section 或 profile 編碼。

配置前准入分兩段：`transport_scan_admission` 由 RVLU／sidecar 輸入長度給出 decode 掃描 work `2*(兩者長度總和)+1`；encode 由已驗證模組快取的掃描量與私有 artifact 容量以 O(1) `transport_encode_scan_admission` 取得。兩者的無配置掃描使用靜態 typed 診斷，因此 scanner temporary=0。掃描後的 `preflight_transport_{encode,decode}` 回傳後續 work、temporary／retained 上界與輸出長度上界；`TransportLimits.max_work` 限制 scan+operation 總和。P14 須對同一不可變輸入先預付公開 preflight 的 scan，再替 producer 的再次 scan+operation 預付額度；只預付 derived operation 會少算第二次掃描。producer 自身先從 `OfficialWorkBudget` 扣除 scan 與 operation，官方子工作額度獨立消耗而不重複扣總額。RVLU 掃描逐筆核對常數、指令、metadata 與 close path 的宣告 count 確有實際 bytes，後續 work 上界納入各 prototype 的 binding／upvalue 重複檢查平方項及 close binding 與指令交叉查找項，不能僅按指令數估算；bounded encoder 的巢狀輸出使用 fallible reserve，native 候選與最後保留模組核對實際 Vec capacity。上下界不足時只回傳 typed error，不交出半成品 VerifiedModule。
